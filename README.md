## 주차별 파일은 세 종류입니다

같은 내용을 세 가지 방식으로 준비했습니다. 순서대로 보시면 됩니다.

| 종류 | 파일 | 용도 |
|---|---|---|
| **강의노트** | `Wxx_LectureNote.mlx` | 수업 중에 함께 보는 문서. 설명과 그림 위주 |
| **실습 스크립트** | `Wxx_01_*.m`, `Wxx_02_*.m` … | 직접 숫자를 바꿔 가며 돌려 보는 코드 |
| **Simulink 모델** | `Wxx_*.slx` | 블록선도로 같은 것을 만들어 확인 |
| **숙제** | `hw/Wxx_HW.mlx` | 수업 중 실습 + 과제 |
| **해답** | `hw/Wxx_HW_Solution.mlx` | 풀이와 해설 |

셋은 서로 짝이 맞습니다. 강의노트의 각 절이 실습 스크립트의 같은 번호 절과
대응하고, 마지막 스크립트(`*_run_simulink.m`)가 Simulink 모델을 돌려서
MATLAB 계산 결과와 같은지 숫자로 확인해 줍니다.

> **그림은 파일을 열자마자 보입니다.** 개념 그림·장치 그림·블록선도는 문서 안에
> 박아 두었기 때문입니다. 그 밖에 값을 바꿔 볼 수 있는 해석 코드가 함께 들어 있어,
> 상단의 **[모두 실행]** 을 누르면 그 결과 그래프까지 채워집니다.

### Simulink 모델은 혼자서도 돌아갑니다

스크립트를 실행하지 않아도 됩니다. `.slx` 파일을 열고 **Ctrl+T** 를 누르면
Scope 창이 자동으로 열리며 결과가 나타납니다.

블록에는 숫자가 아니라 `m`, `b`, `k` 같은 변수 이름이 적혀 있는데도 그냥
실행되는 이유는, 모델을 열 때 기본값을 스스로 준비하도록 설정해 두었기
때문입니다(모델 속성의 PreLoadFcn). 값을 바꿔 가며 실험하고 MATLAB 계산과
숫자로 대조하고 싶을 때만 `*_run_simulink.m` 을 쓰십시오.

### 숙제

각 주차 폴더의 `hw/` 안에 있습니다.

주차마다 **문제 세 개**입니다. 그 이상 내지 않습니다.

| 번호 | 이름 | 난이도 | 시간 | 배점 | 성격 |
|---|---|---|---|---|---|
| 1 | 몸풀기 | 쉬움 | 수업 중 10분 | 30 | 강의노트 코드에서 **숫자 하나만** 바꿔 표 채우기 |
| 2 | 기본 | 중간 | 40분 | 70 | 강의노트와 **같은 절차**를 다른 플랜트에 한 번 |
| 3 | 도전 | 어려움 | 40분 | +10 | **선택 과제.** 안 해도 만점 |

**3번을 안 해도 만점입니다.** 어려운 문제로 점수를 깎지 않습니다.

| 주차 | 1. 몸풀기 (쉬움) | 2. 기본 (중간) | 3. 도전 (선택) |
|---|---|---|---|
| W01 | 이득 $K$ 를 바꿔 표 채우기 | DC모터 속도제어를 같은 절차로 | 출력단 외란의 전달함수 |
| W02 | 댐퍼를 바꿔 극점 따라가기 | RC 회로 모델링 4단계 | 영점 위치와 오버슈트 |
| W03 | 블록선도 손 축약 | 선형화가 몇 도까지 통하나 | 상태공간으로 바꾸기 |
| W04 | 공식과 실측 비교 | 사양에서 극점 찾아내기 | 세 번째 극점의 영향 |

| W10 | 여유 표 채우고 임계이득 찾기 | 사양을 만족하는 이득 고르기 | 견딜 수 있는 시간지연 |
| W11 | Lead 의 $\alpha$ 손 계산 | Lead 설계 5단계 | Lag 로 같은 사양, 비교 |

난이도를 낮추려고 지킨 것들

- 문제마다 첫 줄에 **"강의노트 몇 절을 그대로 보면 된다"** 를 적었습니다
- 강의노트에 나온 플랜트에서 **계수 하나만** 바꿉니다. 새 시스템을 주지 않습니다
- 코드 뼈대를 미리 채워 두었습니다. 학생은 `TODO` 한두 줄만 씁니다
- 손 유도는 한 문제에 **하나까지**
- 문제 구조를 **그림으로도** 보여 줍니다
- 문제지는 빈칸(`TODO`)이 있는 채로 **그대로 실행됩니다**
- 감점 사항은 **세 개 이하**입니다

### 강의노트 서식 (개조식 · 수식)

강의노트와 숙제는 모두 **개조식**으로 쓰고 수식은 **LaTeX**로 넣습니다.
원본 `_src/*.m` 에서 쓰는 표기는 다음과 같습니다.

| 표기 | 결과 |
|---|---|
| `% - 항목` | 글머리 기호 |
| `$...$` | 인라인 수식 |
| `$$...$$` | 독립 수식 (그 줄 전체) |
| `**굵게**` | 굵은 글씨 |
| `` `코드` `` | 고정폭 글씨 |

**주의** — 꾸밈은 겹쳐 쓸 수 없습니다. `` **굵게 안의 `코드`** `` 처럼 쓰면 안쪽
표시가 글자 그대로 남습니다. 누락 검사가 이런 경우를 잡아 줍니다.

### MATLAB 명령어 사용법이 궁금하면

`W01_LectureNote.mlx` 의 **1부**에 `tf`, `pole`, `damp`, `step`, `dcgain`,
`feedback`, `stepinfo`, `lsim`, `sim` 아홉 개를 하나씩 정리해 두었습니다.
각 명령이 무엇을 계산하는지(원리), 무엇을 넣으면 무엇이 나오는지(입출력),
흔히 하는 실수는 무엇인지를 예제와 함께 다룹니다.
이 아홉 개면 1~5주차 계산의 대부분을 할 수 있습니다.

이 주차는 **설계 예제가 중심**입니다. 다섯 문제를 끝까지 풉니다.
다음 주가 중간고사이므로, 강의노트 `0-0-1` 절에 **필수 4단계 / 권장·심화 2단계**
학습 순서와 예상 시간을 적어 두었습니다. 시간이 부족하면 1~4단계까지만 하면 됩니다.

| 예제 | 플랜트 | 사양 | 결과 |
|---|---|---|---|
| A | `1/((s+1)(s+3))` | %OS 10, ts 2 s | 성공. K = 2.1~8.4 (오차 27 % 남음) |
| B | `(s+2)/((s+1)(s+5))` | %OS 15, Tp 1.1~1.4 s | 실패. 궤적이 실축을 안 벗어나 진동이 없음 |
| C | `5/((s+1)(s+2)(s+5))` | ess 0.05, zeta 0.35 | 실패. 오차가 요구하는 K(38) > 안정 한계(25.2) |
| D | `1/((s+1)(s+4))` | %OS 10, ts 2.5 s, \|u\| 10 | PD. 같은 예산이면 z가 클수록 정확 |
| E | C 문제 재도전 | ess 0.05, %OS 20 | PD로는 불가. **PI가 정답** |

적분기가 있는 3차 플랜트(`1/(s(s+2)(s+5))`)의 PD 설계는 `W07_04` 의 3절에서
제어입력 한계와 함께 다룹니다.

숙제의 B·C는 2025년 근궤적 퀴즈 두 문제(제어입력 제약 포함)를 그대로 다룹니다.

```
├─ setup_path.m              학생이 실행하는 경로 등록
├─ build_lecture_notes.m     .mlx 강의노트 생성 (교수자용)
├─ common/                   공통 플랜트 함수

   ├─ Wxx_LectureNote.mlx    강의노트 (배포본)
   ├─ Wxx_NN_*.m             실습 스크립트
   ├─ Wxx_*.slx              Simulink 모델 (배포본)
   ├─ Wxx_build_model.m      .slx 를 코드로 생성 (교수자용)
   └─ _src/                  .mlx 의 원본 스크립트 (교수자용)
```

밑줄로 시작하는 폴더(`_src`)는 `setup_path`가 경로에서 제외하므로
학생이 실수로 실행하거나 이름이 충돌할 일이 없습니다.

### 강의노트를 고치려면

**평소에는 `.mlx` 를 Live Editor 에서 직접 편집하십시오.** 그게 정상 작업 방식입니다.

`_src/*_src.m` 은 처음 만들 때 쓴 원본입니다. 아래 명령으로 다시 생성할 수 있지만
**`.mlx` 에 한 편집을 전부 덮어씁니다.** 큰 개편을 할 때만 쓰십시오.

```matlab
build_lecture_notes('W01')    % W01 만
build_lecture_notes()         % 전체
```

변환 규칙은 단순합니다. `%%` 로 시작하는 줄이 절 제목이 되고, 그 바로 아래
`%` 주석들이 본문 텍스트가 되며, 나머지가 코드 블록이 됩니다.
빈 `%` 줄이 문단을 나눕니다.

**중요 — MATLAB 기본 변환기를 쓰지 않는 이유**

MATLAB이 제공하는 `matlab.internal.liveeditor.openAndSave` 는 한글 문서에서
**내용을 조용히 빠뜨립니다.** 확인된 증상은 두 가지입니다.

1. `%%` 절 제목의 **첫 글자가 한글이면 제목이 통째로 사라집니다.**
   (`0. 몸풀기` 처럼 ASCII로 시작하면 뒤에 한글이 있어도 멀쩡합니다)
2. 여러 줄로 된 본문 문단이 통째로 사라지는 경우가 있습니다.

오류 메시지 없이 조용히 없어지기 때문에 알아채기 어렵습니다.
실제로 W01 강의노트에서 본문 문단 5개와 절 제목 3개가 사라져 있었습니다.

그래서 `mlx_from_script.m` 이 문서 본문을 직접 만들어 넣습니다. 이 함수는

- 절 제목 · 본문 · 불릿 · LaTeX 수식 · 코드를 정확히 생성하고
- **절마다 섹션 구분자를 넣어** Live Editor에서 `Ctrl+Enter` 절 단위 실행이 되게 하고
- 변환 후 **원본의 모든 문장이 들어갔는지 검사**해 빠진 것을 빨간 글씨로 알려 줍니다

추가로 **Live Editor 가 모르는 LaTeX 명령**도 걸러 냅니다.
`\dfrac`, `\dots`, `\iff`, `\underbrace`, `\longrightarrow` 같은 것들은
오류 없이 글자 그대로 남아 버리므로 미리 잡아 경고합니다.

현재 21개 문서(강의노트 7 · 숙제 7 · 해답 7) 모두 **누락 0, 미지원 수식 0** 입니다.

### Simulink 모델을 고치려면

`.slx` 를 직접 편집하시면 됩니다. `Wxx_build_model.m` 은 모델을 코드로
생성하는 스크립트로, 두 가지 용도가 있습니다.

- 모델 구조가 텍스트로 남아 있어 무엇이 어떻게 연결됐는지 한눈에 보입니다
- 모델을 잘못 건드렸을 때 다시 실행하면 원래대로 복구됩니다

주의: `Simulink.Annotation` 의 텍스트에는 슬래시(`/`)를 쓸 수 없습니다.
모델 경로 구분자로 해석되어 오류가 납니다.

### 검증 — 명령 하나로

자료를 고쳤으면 이것을 돌리십시오.

```matlab
verify_all()          % 전체
verify_all('W07')     % 한 주차만
```

네 가지를 자동으로 봅니다.

| 단계 | 보는 것 |
|---|---|
| 1 | 실습 스크립트가 오류 없이 끝까지 도는가 |
| 2 | Simulink 모델이 **워크스페이스를 비운 채로** 도는가 |
| 3 | 문서에 깨진 수식·서식이 남았는가 (`check_mlx`) |
| 4 | 블록선도가 끊기거나 뚫렸는가 (`dg_check_all`) |

3, 4 번이 중요합니다. **수식이 깨져도 MATLAB 은 오류를 내지 않고**,
**블록선도 좌표를 잘못 적어도 그림은 그냥 그려지기** 때문입니다.
눈으로 다 확인할 수 없으므로 자동으로 봅니다.

- `check_mlx` 는 `.mlx`(사실은 zip)를 풀어 본문에 남은 `$`, `**`, 백틱,
  새어 나온 `\frac`, 미지원 LaTeX, 제어문자, 절 구분자 개수를 확인합니다
- `dg_check_all` 은 끊긴 끝점, 블록 관통, 겹친 블록, 외톨이 블록,
  도화지 밖 좌표를 확인합니다

- 실습 스크립트 **46 / 46**
